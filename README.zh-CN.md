# Meshwork

[English](README.md) · [设计文档](docs/design.zh-CN.md)

Meshwork 是一个桌面任务工作台，供人和 AI Agent 一起完成任务。你可以定义可复用的 Bot，为每个项目指定工作目录，再把 Bot 和人工步骤编排成项目工作流。任务从项目启动，任务卡集中记录各步骤的进度、决定和交付物。

## 运行本地桌面预览版

安装 Node.js 24.15 或更高版本、pnpm，以及支持 App Server 的近期版本 Codex CLI。需要登录时执行 `codex login`。Meshwork 使用已安装的 CLI 和已有登录态。自动检测找不到 Codex 时，可以在 Settings 中选择可执行文件。

```sh
pnpm install
pnpm dev
```

1. 打开 **Bots**，选择 **New bot**，定义 Bot 的角色、职责和 Codex 权限。
2. 打开 **Projects**，选择 **New project**，指定一个已有工作目录，按执行顺序添加 Bot 和人工决策步骤。
3. 在项目卡上选择 **Run task** 并输入目标。Codex 结果和人工决定会显示在任务卡上。

SQLite 数据库保存在 Electron 用户数据目录。步骤中断后可从任务卡发起重试。已有的目录绑定 Bot 会转换成带可复用 Bot 步骤的项目，原任务历史会保留。

`pnpm build` 构建应用，`pnpm start` 启动已有构建，`pnpm test` 测试工作流交接与恢复。

## Bot 与本地项目

同一个 Bot 可以在多个项目中使用。例如，定义一次代码审查 Bot，再把它用在目录和审核要求各不相同的两个项目里。任一项目都可以添加人工验收步骤。每个任务使用所属项目的目录和工作流。

## 规划中的团队项目

为团队创建项目，邀请成员用各自的账号加入，并集中管理仓库、文档、任务和交付物。团队项目可以拥有 Bot，工作流可以把步骤派给 Bot 或真实成员，并通过可配置的触发节点启动或继续任务。

例如，同一套代码审核流程可以接收 GitHub PR 或 GitLab MR 事件，触发节点可以选择多个仓库。流程派发 Codex 审核指定版本，将发现保存到项目里，也可以先交给成员确认，再由独立的步骤将报告发布回来源平台。其他流程也能通过手动触发或 Webhook 处理仓库之外的任务。

## 任务在哪里执行

桌面端在本机运行个人工作流。按团队部署设计，登记过的桌面或无界面 Linux 执行节点可以执行项目步骤，团队服务端负责协调项目任务并在账号之间同步上下文。Codex 使用执行机器上的登录态和工作区。

## 项目进度

首版聚焦本地个人工作流。团队协作、外部触发和无界面 Linux 执行节点是后续里程碑。架构和验收条件见[设计文档](docs/design.zh-CN.md)。
